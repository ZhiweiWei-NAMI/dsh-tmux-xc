# Known limitations

These are current, intentional or structural limits of dsh-tmux-xc **1.0.0**. They are not bugs to be silently papered over.

| # | Limitation | Detail / consequence | Workaround |
|---|---|---|---|
| 1 | **One DSH process per `$DSH_HOME` registry** | The registry is a DSH storage-domain JSON backend (`$DSH_HOME/storages/dsh_tmux_xc/`, per-record). Writes are **last-write-wins across processes**: two DSH processes sharing one `$DSH_HOME` can overwrite each other's registry entries. | Run a single DSH process per `$DSH_HOME`, or give each process its own `$DSH_HOME`. |
| 2 | **Native terminal and snapshot are separate** | Card title / **Open terminal** creates a new interactive native DSH terminal, waits for writable state and submits a guarded attach command once. Sent chips and **Snapshot** still open read-only output. Requires the native terminal bundle and discovered PowerShell/POSIX shell; cmd/fish and unsafe PowerShell quoting are rejected. | Complete any SSH authentication in the terminal. A submitted command is not proof of attachment. Copy attach remains available. Closing a terminal does not kill the remote tmux task. |
| 3 | **Snapshot is a point-in-time capture** | The snapshot shows the last N captured lines at the time it was fetched; it does not stream, and it is not refreshed automatically (the panel refresh button re-fetches it). Session/window references capture their **active pane**. | Click **刷新** in the snapshot header, or reopen the chip. Use capture for a fresh read. |
| 4 | **No hot reload** | Host code under a profile's `node_modules` is not continuously watched; install/upgrade and config changes take effect only after a DSH restart (and page reload). The **approval switch** itself is read at call time, so changing it does not need a restart. | Restart DSH after install/upgrade or config edits; reload the page. |
| 5 | **Approval still depends on DSH having an approval channel** | The plugin has one switch (default ON). Even with it OFF, DSH's own permission/denial rules and SSH authentication still apply. The dependency is on an **actual ask**: when DSH's permission mode provides no approval channel, DSH denies the ask with its own message (`requires approval, but no approval channel is available`); the plugin never reinterprets that as consent. OFF does **not** require an extra plugin approval card for create/send/delete — an independently installed DSH host deny still blocks them (observed with a custom `tools/pre-execute` deny on create). | Enable approvals in DSH permission settings, or use a permission mode that permits `ask`. Turning the plugin switch OFF cannot override a host deny. |
| 6 | **Restarts invalidate references by design** | tmux `$`/`@`/`%` ids are per-server and reset after a server restart. A reference binds the observed server generation, so a restarted server yields `SERVER_RESTARTED` and a reused name yields `TARGET_GONE` — never a silent redirect to the wrong shell. | Re-reference the current object from the panel after a restart/recreation. |
| 7 | **Local aliases are bound to the exact identity** | A local alias is stored against the resource key, which includes the tmux **server generation**. After a tmux server restart the same-name object is a new identity, so the local alias does not automatically apply. Config hints (`hosts[].aliases`) are matched by name and do survive restarts; a local alias for the exact target wins when present. Alias metadata is **not** removed by unregistering the target and is not erased from chat history; clearing the alias of a target that has disappeared can return `TARGET_GONE` (an observed residual evaluator alias, not remote activity — see #22). | Re-set the alias after a server restart, or use a config hint for long-lived display names. |
| 8 | **Restoring a removed host does not restore its data** | Host removal purges that host's registrations and aliases. **高级详情 → 恢复** only makes the host visible again; the purged registrations and aliases are gone. The profile config file is never edited by the panel. | Re-adopt/re-alias the targets, or delete the host block from the profile config to remove it permanently. |
| 9 | **Capture is plain text (no colors)** | `capture-pane` output is stripped of ANSI/OSC/DCS sequences and other controls as part of untrusted-data sanitization. Colors and cursor control are not preserved. The snapshot is rendered as text, never HTML. | Read the pane in a real terminal (Copy attach) when visual fidelity matters. |
| 10 | **`submission` is a heuristic; delivery is not execution** | After Enter the plugin waits ~300 ms and captures the cursor line. `pending` means the last ≤24 visible characters of the sent text still appear there (probably an input box); `cleared` means they no longer do; `unknown` means the probe failed (no usable cursor line); text with no visible characters (e.g. whitespace only) is classified `cleared` with a detail saying there was nothing to compare. `delivered` only says bytes reached the pane. `delivered.enter` may be `'unknown'` after an interrupted dispatch. `cleared` is **not** proof that a program executed anything. | Check `submission.state` and `tmux_xc_capture` before claiming a task ran. If input is genuinely stuck, **capture first**, then use **one** Enter form only — `keys: ["Enter"]` without `enter: true`, or `enter: true` without an Enter key — and capture again. Never replay the text blindly; never combine both forms. |
| 11 | **Copy-attach is not verified on Windows PowerShell 5.1, and PowerShell was not executed by the independent evaluator** | The Bash form was executed on Linux by the independent SOL evaluator. The PowerShell form was verified by the **project manager** with **PowerShell 7.6 on Linux**, in both **Standard** and **Legacy** argument-passing modes; SOL did not execute PowerShell. **Windows PowerShell 5.1 + Windows OpenSSH** has not been verified. `cmd.exe` is **unsupported** (different `%`/quoting rules). **Prerequisite:** the copied string is only `ssh <alias> …`, so the alias and its `~/.ssh/config` entry (port, user, jump host, `-F` file) must exist **on the connecting machine**; `-o ClearAllForwardings=yes` applies to the ssh forms only, and a failed copy leaves the clipboard unchanged. | Verify the copied PowerShell command on your Windows host and report the PowerShell version/argument-passing mode; use PowerShell, never `cmd.exe`. Confirm the ssh alias works from the machine where you paste the command. |
| 12 | **Windows desktop is documented, not developer-verified** | Windows desktop + Windows OpenSSH client is documented as instructions and expected to work, but has not been exercised by the developer; the user verifies it ([INSTALL.zh-CN.md](INSTALL.zh-CN.md) §验证清单). This is not a tested support claim. | Report Windows findings against the checklist. |
| 13 | **Reference re-announce runs remote resolves** | After `/compact`, the plugin re-announces the conversation's references to the agent, and each reference is resolved against fresh remote state (an ssh round-trip) before the agent acts. This is intentional freshness, but it costs latency per step/reference. | Keep reference lists short; the agent re-resolves lazily only when it actually uses them. |
| 14 | **`registryScope: profile` uses a hashed profile key** | The profile-scoped domain name is `dsh_tmux_xc_p_<profile>`, where the profile component is derived from the profile name. The key is not the raw profile string and is not meant to be read by hand. | Prefer `registryScope: user` for a single shared registry across the OS user's `$DSH_HOME`. |
| 15 | **`transport: local` only for DSH on the tmux host** | Local transport is supported only when the DSH process runs on the same Linux/macOS host as tmux (Bash observed on Linux). It is not a Windows option and cannot bridge to a remote host. The Bash copy-attach entry then contains the local tmux command only (no ssh); the PowerShell entry is **disabled with an explanation** for a local host, not an enabled choice that fails. | Use `transport: ssh` (default) for any remote host, including a Windows DSH host. |
| 16 | **Same-version reinstall keeps old files** | pnpm treats an unchanged version + path as installed; use `remove` then `add` (or bump the version). | Always restart DSH after reinstalling. |
| 17 | **`registry: memory` is explicit-only** | Persistent-storage failures disable operations (`REGISTRY_UNAVAILABLE`) instead of silently falling back; set `registry: memory` only when you accept losing everything on restart. | Fix the storage directory, or opt into memory deliberately. |
| 18 | **No workspace filter in the panel** | 0.1.1 shows tasks from all workspaces; the old 当前工作区/全部 toggle was removed. The inventory route still accepts `workspace`, but the panel always requests `all=1`. | Use the host/task tree and, if needed, the agent tools' `workspace`/`all` parameters. |
| 19 | **Live refresh is polling, not push** | The panel polls the registry version every ~3 s while visible and refetches inventory only when the version changes; remote state that does not touch the registry (e.g. a pane's output, a process exiting) is not detected until a manual/inventory refresh. | Click **刷新** (or reopen the panel) for fresh remote state. |
| 20 | **Each pre-step re-resolution costs one remote round trip per host/socket** | Only when a conversation has references and a new user batch or a compaction occurred. | Keep reference lists short. |
| 21 | **tmux 3.0a `detach-client -s` needs an attached client** | The plugin enumerates clients and detaches each by name instead; zero attached clients is reported as `detached 0`. | Expected behaviour; no action. |
| 22 | **Unregister is non-cascading and does not erase metadata** | **取消登记** removes only that one registry record: registered descendants stay registered, and aliases and chat history are not purged. A later attempt to clear the alias of a target that no longer exists can return `TARGET_GONE`. This was **observed** with a residual evaluator alias after its target was deleted; it is disclosed observation, not an intentional guarantee that every alias is retained. No remote process is implied by such metadata. | Purge aliases/registrations deliberately if needed; do not read leftover metadata as evidence of a live remote target. |

## Fixed in 0.1.1 `c600ece` — not current limitations

These were real defects in a 0.1.1 build at `1ee6f78` and are **fixed in the accepted candidate** (`c600ecedf2e5504481e89a6aa8439478dd6b2a8d`, tarball SHA-1 `b39fe0019ebffd6aeb49a78b7f86362bf72dea07`). Evidence: independent SOL clicks reported in `.work/review/SOL-RECHECK.md` (not shipped), independent ASTRA acceptance in `.work/review/ASTRA-ACCEPTANCE.md`, and the summarized results in [TEST-RESULTS.md](TEST-RESULTS.md). This decision does not certify any later implementation change.

- **Multi-digit pane acknowledgement:** literal `%N` was being expanded by tmux 3.0a's `display-message`, so text was typed but Enter's guard refused and submission reported `OUTCOME_UNKNOWN`. Fixed at the output-format boundary only; target operands, identity guards and nonce-framed matching are unchanged.
- **Sent-history reference rendering:** a sent tmux reference with a spaced label could be consumed by the generic file-mention renderer and open a nonexistent file. The tmux sent-user-text rule now takes precedence (registered before the generic file rule), and existing stored messages re-render as tmux chips. Tested sent-history/stale paths select the exact target or fail stale; renamed targets and other browser parsers were not tested.

## Also by design (not limitations)

- Discovery/adopt never modify remote tmux (no options, env, or test commands injected).
- **Live discovery ≠ registration:** a new shell-created target can appear in the panel after a refresh without adoption; adoption is what registers durable metadata (badge, alias record, recovery basis).
- detach ≠ unregister ≠ kill: detach kicks clients (processes keep running); **取消登记** removes one registry record only; kill destroys exactly one remote object.
- **移除主机** never edits the profile config file and never kills the tmux server; remote removal terminates only the selected sessions and removes the host locally only when every selected kill succeeded.
- `synchronize-panes` windows refuse input (a pane can't be targeted uniquely).
- Untrusted remote output is sanitized and fenced; tokens inside captured output are never parsed as references.
- Config aliases (`hosts[].aliases`) are display-only; identity is never derived from them, and local aliases take precedence for the exact target.
