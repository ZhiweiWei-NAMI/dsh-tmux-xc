# RV1 — independent code review

Static, read-only review of the supplied snapshot, `lib/**/*.js`, and `test/**`, against PRD/DESIGN/CONTRACTS and the installed DSH 0.2.1-rc.2 source. No tests, DSH, tmux, or ssh were run. ## Evidence and review notes

### tmux 3.0a source evidence

- **[T1] Format-to-shell path:** [`cmd-new-session.c`](https://raw.githubusercontent.com/tmux/tmux/3.0a/cmd-new-session.c) expands the raw `-c` for session creation and passes the original argument to spawning; [`spawn.c`, `spawn_pane`](https://raw.githubusercontent.com/tmux/tmux/3.0a/spawn.c) expands `sc->cwd`. [`format.c:2013–2027`](https://github.com/tmux/tmux/blob/3.0a/format.c#L2013-L2027) creates the format tree with flags zero; [`format.c:1908–1930`](https://github.com/tmux/tmux/blob/3.0a/format.c#L1908-L1930) processes `#()` through `format_job_get`, which invokes `job_run`. [`job.c`](https://raw.githubusercontent.com/tmux/tmux/3.0a/job.c) forks and executes the command with `sh -c`. Thus POSIX single quoting does not close this second interpretation boundary.
- **[T2] Send semantics and server-local ids:** [`cmd-send-keys.c`](https://raw.githubusercontent.com/tmux/tmux/3.0a/cmd-send-keys.c) routes both hex bytes and named keys through `cmd_send_keys_inject_key` → `window_pane_key`. [`window.c`](https://raw.githubusercontent.com/tmux/tmux/3.0a/window.c) broadcasts under `synchronize-panes`; it also defines server-local `next_window_pane_id`/`next_window_id` counters. Copy mode/input-disabled/dead panes can also consume or discard keys, so a success contract should check those states rather than equating command acceptance with delivery.

### DSH findings: exact installed implementation

- **[D1] Actual approval display:** `P/dsh-tools/lib/index.js:3551–3557` forwards reason/displayReason/callId. `P/dsh-client-ui-approval/lib/client.js:38–46,109–115` renders the localized reason as plain React text, not Markdown/HTML. `P/dsh-client-ui-chat/lib/client.js:151–171,13329` supplies only correlated `args.command` as standard detail; there is no automatic full tmux-argument display.
- **[D2] Lifecycle:** `P/cordis/lib/index.js:335–344,371–379` implements listener registration/removal; `:1372–1383` unloads effect disposers. `P/dsh-storage-domain/lib/index.js:348–356` explicitly makes the consumer responsible for close and rejects a second open.
- **[D3] Lossless tool output:** `P/dsh-tools/lib/index.js:2672–2679,3637–3648` snapshots/validates before rendering. `P/dsh-util-values/lib/index.js:713–739` recursively rejects undefined-valued properties.
- **[D4] Accepted batches/steering:** `P/dsh-agent-loop/lib/index.js:809–810,902–918,955–958,1008,1067–1072` supplies newly claimed messages and supports next-step steering. The official reference hook handles every accepted batch: `P/dsh-session-reference/lib/index.js:470–477,487–508`.
- **[D5] Composer coordinates:** `P/dsh-client-ui-conversation/lib/client.js:15676–15684` publishes draft as clipboard text; `:14283–14308` projects chips to one detect character; `:14503–14504,15309–15314` require detect-coordinate spans. `:14913–14916` provides `captureInsertion()`.

### Coverage and boundaries

- The four requester-excluded issues are intentionally not findings: apply-time connection probing/404, missing `transport:local` plumbing, non-transport failures categorized as unreachable, and leftover integration socket files. GUI findings above remain distinct once routes are mounted.
- Existing tests explain the integration blind spots: `test/unit/tools-policy.test.js:23–43` uses a fake runtime; `test/unit/service.test.js:113–121` and `test/integration/helpers.mjs:94–98` use memory storage. `test/integration/service.test.mjs:130–159` restarts before resolution, not between guard/action or creation/reread. `test/integration/concurrency.test.mjs:31–45` uses separate sessions, not synchronized panes. There are no client, hook, route, or plugin-disposal tests in the supplied test tree.
- No additional verified HTML sink, agent/browser ssh-option/socket allow-list escape, host-key weakening, or stored credential defect was found. React text rendering and the configured argv boundary are not themselves findings. This is static evidence, not a Windows/GUI execution certificate.
